# 各版本要装什么模组（Fabric）

这套工具要装**两个**模组：一个**下载器**（把服务器地图存到本地）+ 一个**记录模组**
（记末地柱子 / 史莱姆区块 / 哈希种子）。两个都得对上你的游戏版本。

## 一张表

| 游戏版本 | 下载器（`mods/` 里挑） | 记录模组（`mods/multi/` 里挑） | 能算出完整种子吗 |
| --- | --- | --- | --- |
| **1.21.10** | `simple-world-downloader-1.1.0+1.21.10-swdpathfix.jar` | `seedhelper-1.1.0+1.21.10.jar` | ✅ |
| 1.21.1 / 1.21.4 | `archive-world-downloader-1.20.4.jar` 起最近的那个 | `seedhelper-1.1.0+1.21.1.jar` / `+1.21.4.jar` | ✅ |
| 1.20.6 | `archive-world-downloader-1.20.4.jar` | `seedhelper-1.1.0+1.20.6.jar` | ✅ |
| 1.20.1 / 1.20.4 | `archive-world-downloader-1.20.1.jar` / `-1.20.4.jar` | `seedhelper-1.1.0+1.20.1.jar` | ✅ |
| 1.19.4 | `archive-world-downloader-1.19.4.jar` | `seedhelper-1.1.0+1.19.4.jar` | ✅ |
| 1.18.2 | `archive-world-downloader-1.18.2.jar` | `seedhelper-1.1.0+1.18.2.jar` | ✅ |
| 1.17.1 | `archive-world-downloader-1.17.1.jar` | `seedhelper-1.1.0+1.17.1.jar` | ✅ |
| 1.16.5 | `archive-world-downloader-1.16.5.jar` | `seedhelper-1.1.0+1.16.5.jar` | ✅ |
| **1.14 / 1.15** | 有下载器，但记录模组编不出 | ❌ | ❌ 客户端拿不到哈希种子 |
| 1.12 及以前 | ❌ Fabric 基本没人用 | ❌ | ❌ 结构算法也变了 |

> 1.20.5 及以上也可以用官方那个 `Simple World Downloader`（Modrinth 上同名项目），
> 我们从 1.20.5 起改用了它。更老的版本用 `Archive World Downloader`（同一个作者的另一套，Fabric 覆盖 1.14.4~26.3）。

## 为什么 1.14 / 1.15 不行

破解种子靠四路信号，其中**最关键的一路是"客户端哈希种子"**（`sha256(种子)`，
游戏登录时下发给客户端的，拿到它就能把完整 64 位种子定死）。

**这一路是 1.16 才加的**。1.14 / 1.15 的客户端压根收不到这个值，模组也就无从记录。
没有它，最多只能解出低 48 位 —— 算结构够用，但不是完整种子。

再加上那两版的 Mojang 映射里少了好几个我们用的类（`BiomeAccess` 之类），
给它们单独写一套的成本不划算，所以这套工具的下限就定在 **1.16.5**。

## 怎么自己加别的版本

如果你玩的版本不在表里（比如 1.19.2、1.20.2），可以自己编：

```bash
python3 tools/build-mods.py --only-seedhelper 1.19.2      # 编记录模组
python3 tools/build-mods.py --only-swd 1.19.2             # 编下载器（自动打补丁）
```

编完产物在 `mods/multi/`。构建脚本会自动下 Mojang 客户端、Fabric 映射和 fabric-api
（≤1.18.2 的 fabric-api 在 maven 上只有空壳，脚本会改从 Modrinth 取）。

下载器也可以直接去 Modrinth 下：搜 `Archive World Downloader` 或 `Simple World Downloader`，
按你的游戏版本挑 Fabric 版。

## 结构参数是按版本分家的（重要）

算结构靠的是每个结构的「**盐 + 间距 + 间隔**」三个数。这三个数**各个版本不一样**，
不是改个版本号就完事。查 cubiomes 的参数表（`finders.c`）能看得很清楚：

| 结构 | 1.17 及以前 | 1.18 起 |
| --- | --- | --- |
| **村庄** | salt 10387312，间距 **32**，间隔 8 | salt 10387312，间距 **34**，间隔 8 |
| **下界废弃传送门** | salt 34222645，间距 **25**，间隔 10 | salt 34222645，间距 **40**，间隔 15 |

还有几处是"1.15 → 1.16"或"1.16 → 1.17"的断点（盐值不同、位置全变）：

| 结构 | 断点 |
| --- | --- |
| 海底遗迹 / 沉船 | 1.15 → 1.16 |
| 下界要塞 | 1.15 → 1.16 |
| 末地小岛 | 1.16 → 1.17 |
| 沙漠水井 / 紫水晶洞 / 末地折跃门 | 1.17 → 1.18 |

**实测**：同一种子，`findstruct` 用 1.16.5 和 1.21.10 算出来的海底神殿位置完全不同
（一个在 (392,-872)，一个在 (744,-1992)）—— 这就是参数不同导致的。

### 对我们意味着什么

- 我们自己实现的破解核心（`SeedCracker.java`）里的参数表，目前是按 **1.18.2 起** 那套写的，
  对 1.16.5 / 1.17.1 的村庄、下界传送门、沙漠水井、紫水晶洞、末地折跃门会算错。
- 好消息：**末地柱子和哈希种子不受影响**（跟结构参数无关），所以种子还是能解出来。
- 要支持 1.16.5 / 1.17.1 的结构查询，参数表得按版本分支，照 cubiomes 那张表抄就行
  （`mc <= MC_1_17` 用 `s_village_117`，等等）。
按你的游戏版本挑 Fabric 版。
