# MC 种子工具包

**从下载的服务器地图里反推出世界种子，再用种子算出各种结构的坐标。**
纯客户端工具：不碰服务器、不用 OP、不用管理员权限。

> English version: [README.md](README.md)（GitHub 首页现在显示英文那份，这里是中文原文）

---

## 30 秒上手

| 你的环境 | 怎么启动 |
| --- | --- |
| **Windows** | 双击 **`START.bat`**（Java 用包里自带的，中文不乱码） |
| **WSL / Linux** | 进到本目录，跑 `bash run.sh`（别用 `./run.sh`，解压后可能没执行位） |

启动后是一个菜单：

```
  1. 计算种子（需要下载的存档）      ← 第一次先选这个
  2. 计算结构 / 坐标（用种子 + 版本）
  3. 设置（种子 / 版本 / 存档路径）
  4. 检查更新（联网看有没有新版本）
  5. 反馈问题（带上日志一键发给作者）
  6. 用户协议 / 隐私政策
  7. 导出 / 复制结果（剪贴板 / txt / json / mcfunction）
  0. 退出
```

选 `2` 进去是结构菜单，编号是**连着的 1 ~ 31**：前 22 个是原版结构（海底神殿、末地城、
要塞…），后 9 个是特殊功能（末地船、结构总览、群系查询、史莱姆区块、矿石分布…）。

其中 **31 矿石分布** 是数你**下载好的存档**里有多少矿，按区块排出"哪块最密"（钻石会连
深层变种一起数，还能按 y 范围筛）。它数的是真实方块，所以准；代价是只覆盖你下载到的范围。

> 直接双击运行的版本**自带 Java**（`runtime/`）。如果这个目录里没有 `runtime/`，
> 那你拿到的是精简版，需要机器上有 Java 17+ 或装过 Minecraft（工具会自己去找）。
> Python 需要 **3.8+**，Windows 去 <https://www.python.org/downloads/> 装，安装时勾上
> **"Add python.exe to PATH"**。

## 界面

菜单、结果都是配好色的文字界面，框线用 `╭─╮` 画的（中文按两个格子算宽度，不会歪）。
在真终端里自动开颜色；被重定向/管道接走的时候自动变纯文本，所以脚本里调用很干净。

| 想干嘛 | 环境变量 |
| --- | --- |
| 强制开颜色（比如 IDE 控制台没识别出来） | `MC_UI_COLOR=1` |
| 强制关颜色 | `MC_UI_COLOR=0` 或 `NO_COLOR=1` |
| 框线画不出来（极老的控制台） | `MC_UI_ASCII=1` 会退回 `+--+` 的 ASCII 框 |

界面宽度会**跟着终端走**（夹在 46~68 列之间）—— 窗口拉窄了框线也不会折行糊掉。

## 导出结果

主菜单选 `7 导出 / 复制结果`，可以把刚查到的结果：

| 导出成 | 用途 |
| --- | --- |
| **剪贴板** | 直接粘聊天框 / 记事本（Windows 用 `clip`，WSL 自动走 `clip.exe`） |
| **.txt** | 原样存一份 |
| **.json** | 坐标抠成结构化数据，给别的脚本用 |
| **.mcfunction** | 丢进 `datapacks/mcseed/data/mcseed/functions/`，游戏里 `/reload` 后 `/function mcseed:mcseed` 就能一路传送过去 |
| **地图 .svg** | 把这次的点画成一张图，浏览器打开就能看 |

命令行也能用：`python3 app/export.py --last 3 --format mcfunction`。
所有查询结果都会另存一份 `记录/结果.jsonl`（一行一条），所以随时能翻回去导出。

地图会**按维度分栏**（主世界 / 下界 / 末地是三个不同的坐标空间，混在一张图上比例尺会被拉爆），
每栏自己有刻度、比例尺和编号，底部有对照表。纯手写 SVG，不用装任何东西。

## 更新出问题了？回滚

主菜单选 `8 回滚到旧版本`。每次更新前都会把旧文件留在 `记录/.update-backup/<版本>/`，
所以能倒回去（连那次被删掉的废弃文件也一起放回来）。回滚只动备份里有的文件，
种子、记录、自带 Java 一概不碰。回滚完重启一下就是旧版本了。

## 崩了会直接问你要不要上报

程序崩掉时会打印一段错误信息，并**直接问你**"把这段报错发给作者吗？"——
答 y 就把堆栈 + 日志发到反馈站，不用你再去菜单里翻。答 n 也没关系，
报错已经写进 `记录/日志.txt` 了，随时可以用主菜单 5 发。

## 算种子的时候能看到进度

枚举 2^32 个候选、以及用哈希定高 16 位这两步，都会实时显示进度条：

```
  枚举低 48 位候选  ████████████░░░░░░░░░░░░  52.3%   已用  3s  预计还要   3s
  用哈希定高 16 位  ████████████████████████ 100.0%   已用 11s
```

以前这两步是黑盒 —— 几十秒到几分钟屏幕不动，用户分不清是在算还是卡死了。

## 自己跑测试

```bash
bash tools/tests/run-tests.sh           # 单元 + 集成，几十秒
bash tools/tests/run-tests.sh --quick   # 只跑单元，几秒
bash tools/tests/run-tests.sh --full    # 再加上慢的
```

集成测试会在**临时沙箱**里复制一份工具包再跑，不碰你自己的存档和记录。
发布脚本 `publish.sh` 每次发布前都会自动跑 `--quick` 那档，**不过就拒绝发布**。

**最快的路子**：主菜单选 `5 反馈问题` —— 写两句现象，工具会把**日志自动打包**提交过去，
给你一个编号，作者那边就能看到。

也可以直接开网页填：<https://mcseek.bony-doorframe-shortly.top>

### 日志里有什么（以及没有什么）

每次运行都会往 `记录/日志.txt` 写一行行记录：启动环境（版本 / 系统 / Python / Java）、
你在菜单里点了什么、每条查询的参数和出结果的行数、更新过程、报错和完整的调用堆栈。

**种子、存档路径、用户名这些会先打码再写进去**（`<种子>` / `<路径>` / `<用户>`），
所以日志可以直接发出来，不用担心把世界种子交出去。

日志超过 512KB 会自动轮转成 `日志.1.txt`，不会越堆越大。不想让它自动上传就设
`MC_FEEDBACK_NO_UPLOAD=1`，那样只会帮你打包成 `记录/反馈包-<时间>.zip`，你自己发。

> 作者视角：收到的反馈存在访问机器的 `mcseek/data/`，管理页是
> `https://mcseek.bony-doorframe-shortly.top/admin?key=<secret.txt 里的那串>`。

## 版本号怎么定

界面上显示成 **V1.5.0**，是「**主版本 . 小更新 . 补丁号**」三位
（`app/VERSION` 文件里存的是 `1.5.0`，写成 `V1.5.0` 也认，会自动去掉 V）：

| 位 | 什么时候 +1 | 例子 |
| --- | --- | --- |
| **主版本** | 大改：玩法变了、破解流程变了、老配置不通用 | 1.x.x → 2.0.0 |
| **小更新** | 加功能：新结构、新界面、新能力 | 1.4.x → 1.5.0 |
| **补丁号** | 修 bug / 改错字 / 调文案，功能没变 | 1.5.0 → 1.5.1 |

改完 `app/VERSION` 跑一次 `publish.sh`，客户端下次启动就自动更新
（只要比本地大，不管大在哪一位，都会拉）。

## 自动更新

每次启动工具，它会先看一眼线上有没有新版本。**有新版就把面板摆出来问你一句**：

```
╭ 发现新版本 ──────────────────────────────────────────────────╮
│ 当前版本 1.9.3      新版本 1.10.0   （稳定版通道）           │
│ 更新说明                                                     │
│   1.10.0 正式版：① 发布分稳定版/测试版两个通道…              │
│ 这次会改这些                                                 │
│   这次更新：改 5 个、新增 0 个、废弃 0 个，其余 116 个文件没动│
│     改  app/calc.py                                          │
│     改  app/updater.py                                       │
╰──────────────────────────────────────────────────────────────╯
❯ 现在更新吗？[Y/n]（n = 这次先不更新，下次启动还会问）:
```

答 `y` 才下载替换；更新过程里会**逐个文件列出改了多少行**，更新完再问一句
要不要立刻用新版重启。答 `n` 就当没这回事，下次启动还会问 ——
想手动查随时主菜单选 `4`。

没新版 / 没网 → 什么都不做，最多多等几秒。想在脚本里跑（不要交互）：
设 `MC_NO_UPDATE_ASK=1` 就是老行为（有新版直接悄悄更）。

更新**只换程序**，`.mc-tool.json`（你的种子）和 `记录/` 一个字都不动。
想手动查：主菜单选 `4`。不想让它联网：启动前设 `MC_NO_UPDATE=1`。

### 两个通道：稳定版 / 测试版

| 通道 | 你会拿到什么 | 适合谁 |
| --- | --- | --- |
| **稳定版**（默认） | 只有作者觉得靠谱的版本 | 大多数人 —— 只想安安静静用 |
| **测试版** | 新功能先给你试，可能带着半成品 | 愿意帮忙试、出问题愿意反馈的人 |

两个通道是**两条独立的清单**（`manifest.json` / `manifest-beta.json`），
所以稳定版用户**永远不会**被推去测试版 —— 哪怕测试版号更大。

怎么切：主菜单 `3 设置` 里最后一项。测试版用户等正式版发出来时会自动跟上来
（`1.10.0-beta.1` → `1.10.0`）。想临时试一下：启动前设 `MC_UPDATE_CHANNEL=beta`。

作者怎么发：`bash publish.sh --beta "说明"` 发测试版，不加 `--beta` 就是稳定版。
发稳定版时会顺手把测试版清单也推到同一版本（除非测试版已经跑在前面）。

### 更新前会告诉你改了什么

清单里带着**每个文件的哈希**，所以不用先下载就能算出这次要改哪些文件：

```
  这次更新：改 18 个、新增 0 个、废弃 0 个，其余 103 个文件没动
    改  app/calc.py
    …
  代码差异（18 个文件）：
    app/calc.py      +12 -3
    app/ui.py        +5 -1
    完整 diff：记录/更新日志/1.9.1→1.10.0.diff
```

完整 diff 是标准 unified diff，存在 `记录/更新日志/` 里随时能翻。
顺带还能认出**废弃文件**（上次发过、这次没有了）：只删"确实是我们发的、你没改过"的，
而且是挪进备份不是直接删。

### 替换是怎么做的（以及为什么不慌）

```
拉清单 → 下载到 %TEMP%（边下边算 sha256）→ 校验 → 解压到临时目录 → 逐个文件覆盖
```

- **先比后写**：内容一样的文件直接跳过。正常升级往往只有几个文件真的变了，
  这次 1.5.0 → 1.5.1 就是「替换 1 个，跳过 113 个」。
- **原子替换**：先写 `xxx.new`，再 `os.replace` 换过去。中途断电也不会剩半个文件。
- **被占用会自动重试**：Windows 上文件可能被别的程序或杀毒软件占着（`WinError 32`），
  会按 0.3 / 0.8 / 1.5 秒退避重试三次。
- **失败分轻重**：`app/` 里的代码没换上才算"更新失败"（下次启动自动重试，且不记新版本号）；
  `out/`、文档、脚本这类被占用会提示一下，先按旧的用。
- **覆盖前先备份**：旧文件存到 `记录/.update-backup/<版本>/`，只留最近 3 个版本，能手动倒回去。
- **更新完清 `__pycache__`**：免得 .pyc 跟新代码对不上。
- **白名单**：`.mc-tool.json`、`记录/`、`logs/`、`runtime/`、`.build-cache/` 一律不碰
  —— 自带的那份 Java 也因此在升级时是安全的。

> 为什么会说"重启一下工具就是新版"？因为 Python 导入模块时是把源码读进内存的，
> 正在跑的这一份不受影响（**Windows 也不会锁 `.py` 文件**，只有正在执行的 `.exe/.dll` 才锁），
> 新代码下次启动才生效。

### 安全：为什么域名被黑了也推不动你的工具

更新的下载地址是一个域名，光靠 HTTPS 挡不住"域名被劫持 / 服务器被黑"
—— 那种情况下攻击者能合法地给你返回恶意内容，还能算出"正确的" sha256。

所以发布清单是用 **Ed25519 离线签名**的：私钥在发布机上（不在网站目录里），
公钥内置在客户端里。**签名对不上就不下载、不解压、不替换**，还会大声警告。
清单里改任何一个字节（版本号、sha256、下载地址）都会验签失败。

完整说明（包括还需要在 Cloudflare / 注册商后台手动开的几项，比如 DNSSEC、域名锁、CAA）：
👉 [docs/安全说明.md](docs/安全说明.md)

## 三件容易踩的事

1. **算种子必须先用下载器下载地图**，而且**末地中央岛一定要下到** —— 那 10 根黑曜石柱
   是最大的信息量。
2. **`.mc-tool.json` 里存着你的世界种子**。要把工具发给别人，先删掉它
   （用 `app/make-zip.py` 打包会自动排除）。
3. 很多服务器把"下载地图 / 破种子"写进规则里了。**用之前先看一眼规矩**。
